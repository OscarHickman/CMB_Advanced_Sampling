# Achievements — DiffCMB

*Condensed record of completed and closed-out work. Full derivation/debugging detail is in git history (the pre-restructure `ROADMAP.md`). The forward plan lives in `ROADMAP.md`. Last updated 2026-07-29 (stale forward-pointers resolved, test count re-verified in-venv during the 2026-07-29 doc audit).*

## Validated foundations

- **Phase 0 — unlensed Gibbs baseline on real Planck data (lmax=300, float64): converged and trusted.** C_ℓ R-hat median 1.026, 0% of multipoles above 1.1; ~48% sampling efficiency. This is the reference everything downstream is checked against.
- **The float32 false-convergence trap was caught and became a standing precision rule**: C_ℓ R-hat can look converged while the alm block's R-hat blows up by orders of magnitude from gradient noise. fp64 end-to-end unless a mixed scheme is explicitly validated.
- **Phase 1 — differentiable lensing operator**: custom TF implementation, gradients w.r.t. both alm and φ validated against finite differences and an independent FD-free gold-standard Jacobian (exact linear deflection-field via unit-impulse alm × analytic weight gradients).
- **Phase 1.5 — dense SHT matrix eliminated (the hard gate)**: matrix-free ducc0 SHT behind `tf.custom_gradient`, forward+backward 0.018s at lmax=300 (~500× under the gate; the dense path was 9.38s and didn't fit in GPU memory). CG symmetry/linearity/PD checks pass matrix-free; the lensing op is graph-traceable.
- **HMC + matrix-free-SHT pivot for the alm sampler — validated 2026-07-13.** Replaces the non-viable messenger-field route (below) with plain HMC at ~0.34-0.6s/sweep (~600-1000× cheaper than messenger), unlocked by a one-line JIT-compile fix (`model.py::psi_tf` disables JIT when `use_matrixfree_sht=True`, since XLA cannot compile through the `tf.py_function` ducc0 escape hatch, commit `e99fdb2`). Multi-chain R-hat gate passed: C_ℓ R-hat max=1.030, median=1.005, 0% above 1.1 — better than the Phase 0 dense-SHT reference's own 4-chain result (max=1.014, median=1.001). alm-block R-hat is high in both the pivot and the reference (median 1.45 vs 1.60) — not a regression, expected gradient-noise behaviour at n_alm≈90k. Net ESS/wall-clock throughput ~31× better than the dense-SHT reference despite ~4× worse per-sample efficiency (cheaper sweeps more than compensate). **Burn-in investigation and SHT audit along the way (apples-to-oranges false alarm, not a bug):** several burn-in lengths were tried before landing on the above — `n_burnin=500` showed severe unresolved drift at l≥200; `n_burnin=3000` fixed l≤150 but l=200-299 still drifted; `n_burnin=6000` (no MAP init) gave median ESS 80.6% but C_ℓ came out systematically 3-6x low vs the Phase 0 reference. That triggered a full matrix-free-SHT correctness audit that exonerated the SHT itself (`scripts/debug_matrixfree_sht_accuracy_production_scale.py`: 5.7e-13 relative error vs `healpy.alm2map` at lmax=300/NSIDE=256; `scripts/debug_matrixfree_sht_gradient_production_scale.py`: 1.8e-7 relative error on the custom-gradient backward pass vs finite differences — both machine precision). The real cause was a benchmark-setup mismatch: every ad-hoc chain in this investigation ran without the trusted reference's MAP initialisation (`--map_steps 0` vs the reference's `--map_steps 2000 --map_lr 0.01 --n_lfs 20`), so burn-in alone had to climb from a naive start (psi≈5.0e9) to the true posterior mode (psi≈4.7e8), exactly matching the observed slow, l-dependent drift. Re-running with the reference's actual MAP settings matched the Phase 0 C_ℓ to 1-3% at every probed l (ratios 0.986-1.025) with no special burn-in schedule needed.
- **Phase 2 pre-production gates — both resolved 2026-07-17/18.** (1) Joint (alm, φ) mixing check at lmax≤50: **MARGINAL, not pathological** — worst ESS fraction 2.07% (alm block), comparable to Phase 0's already-accepted single-block HMC ESS at high l; decision was to proceed with HMC on both blocks, no reparametrisation needed. (2) Block-2 exactness experiment (an unlensed-operator exact Gaussian draw for alm|C_ℓ as a Block-2 shortcut): **FAIL** — worst fractional bias in C_l^TT = 652%, pervasive across l=2-42; weak lensing isn't norm-preserving enough at this S/N for the shortcut to be unbiased. This closed the shortcut and confirmed HMC-on-both-blocks (gate 1's configuration) as the production path.
- **Matrix-free port of the Block 3 (φ) lensing operator — done 2026-07-18.** `lens_map_tf`/`psi_lensed` (`lensing.py`) branch on `model.use_matrixfree_sht` to use a new full-sky ducc0 synthesis (`sht_ducc.py::full_synthesis_tf`) instead of the dense `sph_parts` Y-matrix — removing the last dense-SHT dependency blocking lmax=300 Phase 2 chains (gates 1/2 above only ran at lmax≤50 because Block 3 needed the dense matrix). Verified against the dense-SHT reference to numerical precision on a full-sky model (`tests/test_lensing.py`). (Masked-sky validation followed on the same day — see the masked-sky entry below; this entry's original "not yet validated on a masked sky" caveat is superseded.)
- **lmax=300 smoke run of the matrix-free Block 3 port — PASS, 2026-07-18.** `scripts/smoke_lmax300_matrixfree_lensing.py`, job 11611338: synthetic full-sky data, 20 burn-in + 50 samples, warm-started at truth. Finite samples/logp throughout; alm-block accept 0.860, phi-block accept 0.520 (sane); 53.56s/sweep — confirms the port holds at production scale and unblocked full simulation validation (in progress, see `ROADMAP.md`).
- **Masked-sky matrix-free lensing — validated 2026-07-18** (`tests/test_lensing.py`, f_sky~0.3 polar cap, lmax=20/nside=16). `lens_map_tf` value and `psi_lensed` value+gradient match the dense reference exactly at phi=0 (identity lensing). At nonzero phi the dense-vs-matrix-free gradient comparison itself is invalid, not a matrix-free bug: the dense path only computes the unlensed map at the model's unmasked pixels and zero-pads everywhere else before bilinear deflection-interpolation, an unphysical discontinuity at the mask edge that nonzero-phi deflection can sample — exactly the failure mode `sht_ducc.py::full_synthesis_tf` was built to avoid (full-sky synthesis, so deflected positions falling outside the mask still see real sky). Validated instead by finite differences directly on the matrix-free path (`test_psi_lensed_matrixfree_alm_grad_vs_fd_masked_sky`) — passes on its own terms. Masked-sky matrix-free lensing is now trustworthy; unblocks the planned f_sky~0.016 patch-scale CMBLensing.jl-benchmark sanity check (ROADMAP.md Section 1).
- **Phi-block leapfrog-schedule fix — favorable and robust across 5 seeds, 2026-07-22.** Follow-up to the (unfavorable) Fisher mass-matrix attempt below: tested whether simply lengthening the phi HMC trajectory (`phi_n_lfs`, mass matrix left at the default `'prior'`) fixes the near-frozen phi mixing seen in job 11612969, using a new `scripts/smoke_phi_leapfrog_schedule.py` at the same lmax=12/nside=8 scale as the Fisher smoke test. Result is unambiguous where the Fisher route was not: mean lag-1 autocorrelation of phi power fell monotonically in **all 20/20 seed×multipole combinations** (5 seeds × 4 probed l) as `phi_n_lfs` rose from 20→80→200 (mean 0.745→0.576→0.541), with most of the gain already captured by 80 (diminishing returns 80→200). Confirms the production hypothesis: the adapted phi step size settles small (~6.4e-4 at lmax=300), so trajectory length (`step_size × phi_n_lfs`) — not preconditioning — was the bottleneck at the `phi_n_lfs=10` used in the failed simulation-validation run. Caveat resolved: alm-block accept rate also drifted down as `phi_n_lfs` increased within a seed in this script; checked and it is ordinary RNG-stream progression, not state leakage — `run_gibbs_chain` (`samplers.py`) only reseeds the numpy `rng` (used for the exact C_ℓ|alm draws) from `seed`, while all TF-side randomness (HMC momentum, accept/reject draws) comes from TF's global unseeded stream, which keeps advancing across the three sequential calls per seed in the sweep script; no `tf.random.set_seed` call exists anywhere in `run_gibbs_chain` to reset it. The phi-mixing result is unaffected. Follow-up now closed: the per-sweep cost multiplier was measured locally (`phi_n_lfs=100` at 229.67s/sweep vs `phi_n_lfs=10`'s 44.03s/sweep, 5.2x) and the reworked validation run was submitted at `phi_n_lfs=80` (jobs 11635790 → 11661265; production rate measured at 189s/sweep on gc002 and ~115-120s/sweep on gc006 — see `ROADMAP.md`). This also incidentally surfaced that local (non-SLURM) smoke scripts need the same `OMP_NUM_THREADS=8`/`TF_ENABLE_ONEDNN_OPTS=0` env guards the `.slurm` wrappers already set — without them, TF oversubscribes all 128 login-node cores and a lmax=12 toy run can stall indefinitely from thread contention alone.
- **Fisher-informed phi HMC mass matrix — implemented and unit-tested, but 5-seed local smoke evidence is unfavorable, 2026-07-20.** Attempted fix for the phi-block mixing failure below: added `lensing.py::estimate_phi_diag_fisher` (coordinate-sampled diagonal likelihood-curvature estimate via finite differences of the already-validated analytic `psi_lensed` gradient, validated against a brute-force dense Hessian reference, `tests/test_lensing.py::test_estimate_phi_diag_fisher_vs_dense_hessian_small_lmax`) and `samplers.py::build_phi_posterior_mass_sqrt` (folds that into the prior-only mass matrix, `tests/test_samplers.py`), wired into `run_gibbs_chain` as opt-in `phi_mass_matrix='fisher'` (`'prior'` remains default, verified zero-effect on existing callers via monkeypatch-based non-invocation test; full suite 73/73 passing). **Design note (tried and abandoned):** the first implementation used a true joint-random-direction Hutchinson probe (cheaper, O(n_probes) gradient evals total) but perturbing all packed-phi modes simultaneously crosses the same C0-but-not-C1 bilinear-interpolation-cell boundary documented in `test_psi_lensed_phi_grad_vs_fd`'s eps note; even after rescaling eps to avoid that, the Hessian's off-diagonal coupling was large enough that single-digit probe counts gave estimates off by orders of magnitude (empirically: 3.3e6 vs a true diagonal of ~110). Switched to per-coordinate sampling (same FD computation, applied to a sampled subset of modes per L instead of a joint direction) — stable by construction, costs more gradient evals but runs once after a short burn-in warm-up, not every sweep. **Mixing evidence, not just correctness, turned out unfavorable**: a single-seed smoke test (`scripts/smoke_phi_fisher_mass_matrix.py`, lmax=12/nside=8) initially showed L=2 lag-1 autocorrelation dropping 0.54→0.015 (fisher better), but a different single-seed test at lmax=16/nside=12 showed the opposite (0.37→0.64, worse). A 5-seed repeat at the lmax=12/nside=8 scale settled it unfavorably: mean L=2 autocorrelation went from 0.383 (prior) to 0.495 (fisher) — worse on average, 3/5 seeds regressed. Leading suspect: the one-shot coordinate-sampled Fisher curvature estimate (computed once, from a small `n_probes` sample, at one specific warm-up chain state) may itself be too noisy/state-dependent a preconditioner to reliably help — its own run-to-run stability has not yet been checked directly. Do not re-submit the lmax=300 validation job with this fix until that's resolved.
- **lmax=300 simulation validation — run completed, FAIL/INVESTIGATE, 2026-07-19.** Job 11612969 (`scripts/validate_sim_lmax300_lensing.py`, n_burnin=200, n_samples=1000, warm-started at truth) ran to completion (9.65h, mean alm accept=0.623, mean phi accept=0.738) but failed its own 3σ point-agreement check (worst |z|=6.28). Post-hoc diagnosis: the alm block's large z is consistent with its already-known low ESS (0.7-4.3%, matching gate 1) rather than real bias (frac_bias ≤0.5% everywhere); the phi block's z is more concerning — direct autocorrelation of the phi power (not the Sokal IAT estimator, which misreads this case as ESS=100%) shows lag-1/lag-5 correlation >0.9999 and a smooth near-monotonic drift rather than a converged noisy trace, i.e. the phi block likely never equilibrated within the sampling window. Follow-up resolved: the cause was trajectory length, not step-size adaptation — see the leapfrog-schedule entry above, and `ROADMAP.md`'s Simulation-validation entry for the re-run's status.
- **Beam transfer function + HEALPix pixel window — wired into the likelihood and validated, 2026-07-18.** `power.py::beam_pixwin_transfer(lmax, fwhm_arcmin, nside)` (per-l B_l * pixwin_l, tested against healpy directly) is now threaded through `CosmologyAdvancedSampling(..., beam_fwhm_arcmin=None)` (opt-in, `None` = old behaviour, so all existing call sites are unaffected) and applied as a diagonal multiply on the unlensed alm — after `splittosingularalm_tf`, before SHT synthesis — in `model.py::_psi_tf_raw`, `lensing.py::lens_map_tf`, and `lensing.py::psi_lensed` (not applied to the phi prior term in `log_prob_phi_block`, which is correctly beam-independent). Validated against an independent ground truth (`healpy.almxfl` + `healpy.alm2map`, not the model's own machinery) by isolating the likelihood term via a Ninv-zeroed twin model: `tests/test_model.py::test_psi_tf_beam_pixwin_matches_ground_truth_synthesis` passes with an unbeamed-model negative control confirming the test actually exercises the operator. `lens_map_tf`/`psi_lensed`'s beam application is validated for consistency with `_psi_tf_raw`'s via the existing phi=0-identity invariant (`tests/test_lensing.py::test_psi_lensed_zero_phi_matches_unlensed_with_beam`).
- **Anisotropic per-pixel noise N_ii — wired into the likelihood and validated, 2026-07-29.** The other half of the Section 2 real-data pre-condition. New opt-in `noise_map=None` kwarg on `CosmologyAdvancedSampling.__init__` (`model.py`), same pattern as the beam feature: a length-NPIX per-pixel noise-sigma array building a spatially-varying `self.Ninv = 1/noise_map**2` in place of the uniform `1/_noisesig**2`, in both `data_mode` branches; `None` (default) preserves the old scalar behaviour exactly (verified bit-for-bit). Everything downstream (`Ninv_masked`, `Ninv_parts`, the likelihood terms, and the Fisher-effective-noise mass-matrix calc, which already only used `np.mean(Ninv[unmasked])`) needed no changes — confirmed both by reading the code and empirically. Full suite: 77 passed, 1 skipped, 0 failed — no regressions.

- **Optional Block 4 — C_L^φφ|φ exact inverse-Gamma draw — implemented and validated, 2026-07-29.** `log_prob_phi_block`'s Gaussian prior term on φ has the identical per-L quadratic-form structure (m=0 weight 1, m≥1 weight 2×(re²+im²)) as the CMB alm prior Block 1 already exploits, so the same exact-conjugacy argument gives `C_L^φφ | φ ~ InvGamma(L-0.5, S_L/2)`. New `lensing.py::compute_sl_phi_np`/`sample_cl_phiphi_given_phi` mirror `model.py::compute_sl_np`/`sample_cl_given_alm` exactly, with a widened numerical clip (`[1e-30, 1e10]` vs Block 1's CMB-scale `[3e-7, 3e6]`) since C_L^φφ lives on a very different numerical scale. Validated: an independent brute-force healpy-ordering cross-check of the m=0-vs-m≥1 weighting (the exact failure mode of the "alm precision convention" bug below) to float64 precision; a 3000-realization recovery test at a known constant C_L^φφ, matching the *expected* (bias-adjusted for the flat-prior InvGamma posterior mean, `C0·L/(L-1.5)`) value to within 6 standard errors — still tight enough to catch a gross 2x weighting bug. Wired into `run_gibbs_chain` as opt-in `sample_cl_phiphi=False` (default, verified via monkeypatch non-invocation test to never call the new sampler); when `True`, resamples `cl_phiphi_full` every sweep from the current φ state (same per-sweep rebuild pattern as the alm block's `current_lncl`/`mass_sqrt_np`), rebuilds the φ HMC mass matrix each sweep to match, and adds full checkpoint save/resume support (old checkpoints without the new keys still load via a fallback to the caller-supplied `cl_phiphi_full`). Explicitly rejects combination with `phi_mass_matrix='fisher'` (frozen-at-burn-in mass matrix would go stale against a spectrum that changes every sweep). Full suite at the time of the change: 82 passed, 1 skipped, 0 failed — no regressions, including alongside the anisotropic-noise change above. ## Real bugs found and fixed (each caught by dense-reference validation, not by trusting derivations)

- **φ-block HMC gradient**: the FD backward pass could re-query a shifted angle into a different interpolation cell, producing wild step-size-dependent gradients — replaced with an analytic bilinear-interpolation gradient; the regression tests' own FD ground truth was also unstable and fixed. Block 3 gradients are production-trustworthy.
- **alm precision convention**: uniform 1/C_ℓ used where the real spherical-harmonic convention requires 2/C_ℓ for m>0 — a genuine variance error, though not the cause of any sampler stall.
- **Messenger conditional derivation**: the plausible-looking naive `t|s,d` precision was subtly wrong (needs the reduced noise N−T); caught against an exact dense reference before touching production.
- **SHT operator normalisation**: AᵀA is not a scalar multiple of identity — needs per-mode m=0/m>0 weights *and* empirical calibration (HEALPix quadrature is ~1–2% off the analytic constant, enough to bias specific modes by tens of posterior SEs).
- **HMC + matrix-free SHT JIT-compile incompatibility**: `jit_compile=True` cannot compile through `tf.py_function`, so the combination had silently never run — a one-line fix unlocked ~0.34s/sweep production HMC (see ROADMAP).
- **`tf.gather`/`IndexedSlices` on a custom-gradient output**: `tf.gather` on a `tf.custom_gradient` op's output produces `IndexedSlices`, not a dense tensor, as the upstream cotangent — any `tf.py_function`/`.numpy()` call inside that op's backward pass must `tf.convert_to_tensor()` it first. Surfaced by the matrix-free masked-likelihood path adding a `tf.gather` on `apply_lensing_tf`'s output (fixed in commit `19a7977`); applies to any future custom-gradient op feeding into `tf.gather`/`tf.boolean_mask`.
- **Cosmic variance mistaken for sampler bias (caught before it reached production)**: an early draft of the simulation-validation script (`scripts/validate_sim_lmax300_lensing.py`) compared posterior C_ℓ^TT draws against the CAMB *ensemble-average* input spectrum. At low l (few (2l+1) modes per bin) a single realization's power can differ from the ensemble mean by O(1), producing spurious multi-sigma "bias" that was really just cosmic variance. Fixed by comparing against the *realized* power in the actual drawn alm_true (`model.compute_sl_np`, the same S_l the exact C_ℓ|alm conditional targets) — caught via cheap small-scale local testing (lmax=30/nside=32) before the fix was trusted at lmax=300.
- **`integrated_autocorr_time`'s zero-variance short-circuit was a hidden absolute-tolerance bug, found 2026-07-21.** Both `gate_phi_alm_mixing_check.py` and `gate_patch_mixing_check.py` guarded against a constant (already-converged-looking) input with `np.allclose(x, 0.0)` after mean-subtraction — but phi-power summary statistics at production lmax are naturally O(1e-9) to O(1e-17) in absolute magnitude, well inside `np.allclose`'s default `atol=1e-8`, so *any* real fluctuation in phi power was misread as "no variance" and silently short-circuited to a fake ESS=100%. This produced misleadingly perfect phi-block mixing numbers in **both** the lmax≤50 joint-mixing gate (job 11609120, originally reported as "phi mixes well except l=2") and the lmax=300 patch-scale gate (job 11626450, originally "worst ESS 5.47%"). Recomputing from each run's saved `.npz` samples with a scale-relative check (`np.allclose(x / np.abs(x).max(), 0.0)`) gives real phi ESS of 4.0-37.4% (gate 1) and 4.7-11.7% (patch gate) — comparable to the alm block's ESS in both cases, not near-perfect. Both gates' overall MARGINAL verdicts are unchanged (the alm block was already the binding worst case in both), but the phi-block claims in `ROADMAP.md` were corrected in place; the fix is applied to both scripts so future gate runs report real numbers. Lesson: a "no variance" fallback branch needs a tolerance scaled to the data, not a hardcoded absolute one — the same family of bug as the Sokal-estimator misreading non-stationary drift as ESS=100% in the lmax=300 simulation-validation run, just via tolerance rather than window logic.

## Closed-out sampler routes (do not revisit without new evidence)

- **Phase 0b — diagonally-preconditioned CG on the masked sky: abandoned.** The Jacobi preconditioner degrades ~4 orders of magnitude under a realistic mask (f_sky≈0.74); extrapolated cost 10⁴–10⁵ iterations per Gibbs step. Diagnosed in miniature and quantified.
- **Phase 0c — messenger-field sampler: built, validated at small scale, and closed as non-viable at production scale.** The full arc: correct conditionals validated against dense references; the masked-sky divergence traced to off-diagonal AᵀA coupling; a block-diagonal-by-m correction built that matches the exact dense fix's accuracy (the off-diagonal energy is 99.7% same-m with a parity selection rule); production benchmark at m_group_size=5 = 354.68s/sweep. The production run completed but **failed validation — intrinsic critical slowing down** at n_alm≈90k: ESS 0.6%, C_ℓ biased low, monotonic drift. Systematically ruled out as fixes: more inner iterations (would need ~25–85 *hours* per sweep), τ² annealing (refuted by targeted toy tests — the current τ² is already optimal), mask topology, C_ℓ dynamic range, and the block approximation itself (the exact dense correction mixes equally slowly). The slowdown is dimensionality-intrinsic to plain messenger Gibbs — the known failure mode that motivated messenger-as-CG-preconditioner work in the literature.
