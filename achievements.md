# Achievements — DiffCMB

*Condensed record of what's validated and closed out — current state, not a change log. Full debugging history is in git log. Forward plan: `ROADMAP.md`.*

## Validated foundations

- **Phase 0 — unlensed Gibbs baseline on real Planck data (lmax=300, float64): converged and trusted.** Reference everything downstream is checked against.
- **Phase 1 — differentiable lensing operator**: gradients w.r.t. both alm and φ validated against finite differences and an independent gold-standard Jacobian.
- **Phase 1.5 — dense SHT matrix eliminated.** Matrix-free ducc0 SHT behind `tf.custom_gradient` (~500x under the speed gate; the dense path didn't fit in GPU memory). This is what makes lmax=300+ tractable at all.
- **HMC + matrix-free-SHT alm sampler — production path, validated.** Replaces the abandoned messenger-field route (below); ~31x better net ESS/wall-clock throughput than the old dense-SHT reference. Requires MAP initialisation before burn-in — without it, burn-in looks like unresolved drift even though the sampler itself is correct (confirmed independently: matrix-free SHT matches `healpy.alm2map` to machine precision).
- **Phase 2 pre-production gates, both resolved.** (1) Joint (alm, φ) mixing at lmax≤50 is marginal, not pathological — HMC on both blocks needs no reparametrisation. (2) An unlensed-operator exact-Gaussian shortcut for alm|C_ℓ was **rejected** (652% worst fractional bias in C_l^TT — weak lensing isn't norm-preserving enough at this S/N). HMC-on-both-blocks is the production configuration.
- **Matrix-free port of the φ-block (Block 3) lensing operator — done, full-sky and masked-sky validated.** Removes the last dense-SHT dependency blocking lmax=300 chains. Full-sky matches the dense reference to numerical precision; masked-sky validated by finite differences directly on the matrix-free path (the dense path isn't a valid masked-sky reference at nonzero φ, since its zero-padding creates an unphysical edge).
- **`phi_n_lfs` (leapfrog trajectory length), not the mass matrix, is what controls φ mixing.** Lengthening it (20→80→200) monotonically improved φ-power autocorrelation in every seed/multipole tested, most of the gain already at 80 — production default. A Fisher-informed mass matrix was implemented and correct but made mixing *worse* on average — closed as unfavorable; don't revisit without new evidence the one-shot Fisher estimate isn't too noisy to help.
- **Beam transfer function + HEALPix pixel window — validated, opt-in** (`beam_fwhm_arcmin=None` on `CosmologyAdvancedSampling`, `None` = old behaviour). Validated against an independent ground truth (`healpy.almxfl`+`alm2map`).
- **Anisotropic per-pixel noise — validated, opt-in** (`noise_map=None`, `None` = old behaviour). Validated against an independent ground truth, isolating the likelihood term via a Ninv-zeroed twin model.
- **Block 4 — C_L^φφ|φ exact inverse-Gamma draw — validated, opt-in (`sample_cl_phiphi=True`).** Same exact-conjugacy argument as Block 1's C_ℓ|alm draw. Validated against a brute-force cross-check and a 3000-realization recovery test at known constant C_L^φφ. Resamples the φ prior spectrum every sweep and rebuilds the φ mass matrix to match; mutually exclusive with the Fisher mass matrix. Full checkpoint save/resume support.
- **φ-block memory leak — root-caused and fixed at lmax=32.** Eager-mode `tf.py_function` calls (forced eager because the φ HMC step's deflection-geometry recompute isn't traceable through plain TF ops) register a callback in TF's process-global eager py-function registry on every call and are never freed — a documented TF footgun. Fixed by tracing `bootstrap_results`+`one_step` together in `@tf.function`. Verified ~20,000x RSS reduction at lmax=32. **Caveat: recurred at lmax=128** in a later coverage-pilot run (OOM after ~1200 sweeps on an exclusive multi-TB node) — the fix holds at the scale it was validated at, but isn't confirmed to fully close the leak at production scale. Not yet root-caused further; workaround is restarting the process periodically (the leak accumulator resets), not a real fix.
- **lmax=300 point-validation run at `phi_n_lfs=80` (post-leak-fix): completed, φ-amplitude deficit now diagnosed as under-mixing, not sampler geometry.** Chain itself is healthy (no frozen-block signature, clean alm/C_ℓ^TT recovery), but recovered φ power is systematically under-estimated by roughly half to seven-eighths across l=10-300. `scripts/analyze_phi_deficit_vs_snr.py` (2026-08-06, free post-processing of the existing posterior, no new MCMC) shows the deficit decreases smoothly with S/N (Spearman ρ=-0.78, worst at low S/N) — the signature of an under-mixed/Wiener-suppressed start (Millea, Anderes & Wandelt arXiv:2002.00965), not HMC correlation-length degradation at high S/N (which would predict the opposite trend). Same direction as the lmax=128 pilot's stuck l=[60,100) bin (below) — one phenomenon at two scales. **Not being chased with further lmax=300 compute** — the lmax≈128 coverage-pilot track is the primary exactness evidence and doesn't depend on resolving this, and this finding means the fix is more sampling, not a different integrator.

## Coverage-test prerequisite findings (lmax≈128 pilot track)

- **Strict simulation-based calibration only applies to the fields (alm, φ), not the spectra.** Blocks 1 and 4's exact conditionals are structurally identical to their likelihoods, so the implied prior on each spectrum is flat/improper — there's no `θ_true ~ p(θ)` to rank. Spectra instead get an interval-coverage check against *realized* power (never the CAMB ensemble mean, see the cosmic-variance bug below) — a weaker claim, must be labelled coverage not calibration.
- **A cold alm start can freeze the φ block outright.** A large residual from a cold start gets absorbed by the φ block inflating its low-L amplitude; Block 4 then faithfully tracks that inflated φ and rebuilds the mass matrix from it every sweep, locking φ at near-zero accept — self-reinforcing. Truth-warm-started validation can't catch this (no residual to run away from). Fixed: pilot chains start from a data-driven MAP estimate (never sees the truth) with a raised burn-in and a first-class φ accept-rate floor (0.15) ahead of any trace statistics.
- **Coverage harness is built and smoke-tested, not yet launched.** Gated on the pilot chain returning GO (`ROADMAP.md` tracks current status).
- **The joint (C_ℓ^TT, C_L^φφ) correlation-figure question is open, not answered.** A single-chain pilot found all correlations small, but the chain's own autocorrelation implies too few effective independent draws to trust that — underpowered, not negative. Needs a longer or pooled trace.
- **`phi_n_lfs=80→240` (3x more HMC leapfrog steps): does not fix the l=[60,100) equilibration bin.** Lag-1 autocorrelation only moved 0.996→0.991 (job 11694912, re-analyzed 2026-08-07); still NO-GO on the fixed lag-1 gate, and the near-zero improvement despite 3x compute is itself evidence for a sampler-geometry problem (not just under-mixing), per `ROADMAP.md`'s decision rule 3(a). This triggered the MCLMC spike below.
- **MCLMC spike (Block 3 integrator swap) — GO, promoted to production default 2026-08-08.** Hand-implemented isokinetic-leapfrog MCLMC (Robnik, De Luca, Silverstein & Seljak arXiv:2212.08549) directly in TF (`diffcmb/mclmc.py`; equations ported from blackjax's reference implementation as a spec, no JAX/blackjax dependency — neither is installed and porting the ducc0-wrapped SHT stack to JAX would be a much bigger job than a bounded spike), wired in via `run_gibbs_chain(phi_sampler='mclmc', phi_mclmc_L=...)`, reusing `log_prob_phi_block` and its gradient completely unchanged. Small-lmax=20 findings: an untuned step size (4 orders of magnitude below HMC's converged value) gave a false NO-GO; once tuned (grid search over step_size/L/n_steps on `dine2`, see `scripts/gate_phi_mclmc_vs_hmc.py`), the best config (n_steps=30, step_size=0.1, L=40, vs an over-provisioned n_steps=80 default) beat HMC's ESS/wall-clock-second on 4/6 probed l-bins with a clean bias check (unadjusted-sampler posterior mean agreement, all rel_diff<0.52). **lmax≈128/nside=64 pilot-scale decider (job 11708844, completed 2026-08-08): clear GO.** MCLMC (n_steps=30, step_size=0.1, L=200) beat the recorded HMC baseline (phi_n_lfs=240, matched config) on ESS/wall-clock-second at **every** probed l-bin (2, 27, 52, 77, 102, 127) — largest win at the previously-stuck problem bin l=77: HMC ESS/s=0.0010 vs MCLMC ESS/s=0.0040 (4x), while running *faster* in absolute wall-clock too (3560s vs 8910s for a comparable 300-sweep window, since MCLMC needed only n_steps=30 vs HMC's phi_n_lfs=240 per sweep). Bias check flagged 3/6 bins with rel_diff>0.5 (l=27,77,102), but ESS per bin was only 13-19 samples on near-zero-mean quantities (values ~1e-9 to 1e-15) — read as MC noise, not a systematic offset, though this should be re-checked once the full pilot chain (more samples) is in. `phi_sampler='mclmc'` (n_steps/step_size/L = 30/0.1/200, `scripts/pilot_coverage_equilibration.py` defaults) is now the production Block 3 path; the retired HMC path (phi_n_lfs=240) remains available via `--phi_sampler hmc` for comparison, not deleted. lmax=128/nside=128 equilibration re-run launched (job 11710475) to confirm the win transfers from the ESS/s side-by-side to the actual lag-1/drift equilibration diagnostic the coverage-ensemble gate uses. **Job 11710475 (completed 2026-08-09, 3700 sweeps): NO-GO — the ESS/s win does not transfer.** Same fixed lag-1<0.2-by-lag-200 gate as every prior pilot: [60,100) still stuck (r_200=0.160 but non-monotonic on the way there — 0.184 at lag 100, 0.131 at lag 150, back up to 0.160 at lag 200), [100,128) got *worse* at long lag (drift_sigma=1.10, r_200=0.366, up from r_150=0.132), [2,10) also fails to settle (r_200=0.403). Only [10,30) (first crossing lag 150) and [30,60) (lag 100) look like they're actually converging. Net: MCLMC is a real win on ESS/wall-clock-second (job 11708844) but has not, on this evidence, fixed the underlying equilibration pathology at lmax=128 — same symptom profile as HMC at phi_n_lfs=240 (job 11694912), just faster per sample. Treated as a new, narrower finding per `ROADMAP.md`'s decision procedure — reported to the user, no further tuning run launched unilaterally.
- **MCLMC equilibration pathology root-cause diagnosed — 2026-08-10 (job 11717684, cosma5, 21s).** `scripts/diagnose_equilibration_pathology.py` analysed the 3700-sweep MCLMC npz (`pilot_coverage_lmax128_mclmc_n3300.npz`) using fine-lag ACF (lags 1–500), per-bin power ratio vs truth, and third-by-third drift. ## Real bugs found and fixed (dense-reference validation catches, not derivation trust)

- **φ-block HMC gradient**: a finite-difference backward pass could re-query a shifted angle into a different bilinear-interpolation cell, producing wild step-size-dependent gradients — replaced with an analytic gradient.
- **alm precision convention**: uniform 1/C_ℓ used where the real spherical-harmonic convention requires 2/C_ℓ for m>0.
- **Messenger conditional derivation**: the plausible naive `t|s,d` precision was subtly wrong (needs the reduced noise N−T); caught against an exact dense reference before touching production.
- **SHT operator normalisation**: AᵀA is not a scalar multiple of identity — needs per-mode m=0/m>0 weights *and* empirical calibration (HEALPix quadrature is ~1-2% off the analytic constant).
- **HMC + matrix-free SHT JIT-compile incompatibility**: `jit_compile=True` can't compile through `tf.py_function` — silently never ran until a one-line fix disabled JIT for that path.
- **`tf.gather`/`IndexedSlices` on a custom-gradient output**: `tf.gather` on a `tf.custom_gradient` op's output produces `IndexedSlices`, not a dense tensor, as the upstream cotangent — any `.numpy()`/`tf.py_function` call inside that op's backward pass must `tf.convert_to_tensor()` it first. Applies to any future custom-gradient op feeding into `tf.gather`/`tf.boolean_mask`.
- **Cosmic variance mistaken for sampler bias**: an early validation script compared posterior C_ℓ^TT draws against the CAMB *ensemble-average* spectrum, producing spurious multi-sigma "bias" at low l from ordinary cosmic variance. Fixed by comparing against the *realized* power in the actual drawn alm_true instead.
- **`integrated_autocorr_time`'s zero-variance short-circuit was a hidden absolute-tolerance bug**: `np.allclose(x, 0.0)` guarded against constant input, but phi-power summary statistics are naturally O(1e-9)-O(1e-17) — inside the default `atol=1e-8` — so real fluctuations were misread as "no variance" and silently reported as fake ESS=100%. Fixed with a scale-relative check. Lesson: a "no variance" fallback needs a tolerance scaled to the data, not a hardcoded absolute one.
- **`run_gibbs_chain`'s return-tuple arity depends on which blocks are enabled** (4-tuple with no φ block, 5-tuple with φ, 6-tuple with φ+C_L^φφ) — `scripts/run_lensing_blind_baseline.py` hardcoded a 5-tuple unpack for a no-φ-block call, crashing after a full 3000-sweep chain completed (caught 2026-08-11, see Coverage-test prerequisite findings above). SLURM reported `COMPLETED, exit 0:0` for the crashed run since the traceback was inside Python after the job's own work was done — always check `.err` for a traceback, not just SLURM job state, when harvesting completed jobs.

## Closed-out sampler routes (do not revisit without new evidence)

- **Diagonally-preconditioned CG on the masked sky: abandoned.** Jacobi preconditioner degrades ~4 orders of magnitude under a realistic mask; extrapolated cost 10⁴-10⁵ iterations per Gibbs step.
- **Messenger-field sampler: built, validated at small scale, closed as non-viable at production scale.** Conditionals correct against dense references, but the production run showed intrinsic critical slowing down at n_alm≈90k (ESS 0.6%, C_ℓ biased low, monotonic drift) — dimensionality-intrinsic to plain messenger Gibbs, a known failure mode in the literature. Superseded by the HMC + matrix-free-SHT pivot above.
- **Unlensed-operator exact Block-2 shortcut for alm|C_ℓ: rejected** (Phase 2 pre-production gates above). Not fundamentally dead — a CG solve built from autodiff of the lensed posterior could target the correct conditional exactly — but unexplored and not worth pursuing unless HMC-on-both-blocks becomes a proven throughput bottleneck.

## Engineering gotchas worth remembering

- **Eager-mode `tf.py_function` calls in a hot loop leak memory** — wrap in `@tf.function` instead, tracing once and reusing the graph. If a value must reach a traced function and changes between calls (e.g. Block 4's resampled spectrum), it must be a `tf.Variable` read via `tf.convert_to_tensor`, not a plain Python/numpy value closed over — the latter gets silently baked into the trace as a constant.
