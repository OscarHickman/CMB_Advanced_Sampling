# Research Roadmap: Differentiable Bayesian CMB Analysis

*Forward-looking plan only. Completed/closed-out work — including the full Phase 0b (CG) and Phase 0c (messenger-field) sagas — is summarised in `achievements.md`; full detail in git history. Restructured 2026-07-13.*

**The claim being built:** the first full-sky, curved-sky (HEALPix), differentiable joint Gibbs sampler over (alm_unlensed, C_ℓ, φ). Flat-sky joint sampling exists (CMBLensing.jl); full-sky methods are point-estimate or marginal (MUSE, QE). LiteBIRD-class delensing is structurally inaccessible to flat-sky codes. **The window is finite (curved-sky MUSE announced) — the alm-sampler fix and Phase 2 are the critical path; everything else waits.**

## 0. HMC + matrix-free-SHT pivot — VALIDATED 2026-07-13, root cause of the earlier bias found (not a bug)

The messenger-field route is closed (intrinsic critical slowing down at production scale — see `achievements.md`). The replacement: a one-line JIT-compile fix lets HMC finally run with the Phase-1.5 matrix-free SHT at **≈0.34-0.6s/sweep (~600-1000× cheaper than messenger's 354.68s)**.

- [x] **Fix committed** — `model.py::psi_tf` disables JIT when `use_matrixfree_sht=True` (XLA cannot compile through the `tf.py_function` ducc0 escape hatch). Committed `e99fdb2`.
- [x] **Burn-in-length investigation, several rounds:** `n_burnin=500` showed severe, unresolved drift at l≥200; `n_burnin=3000` fixed l≤150 (ESS 60-100%) but l=200-299 still drifted; a 4500-sweep full-trace run showed the drift *decelerating* late but not conclusively; `n_burnin=6000` (no MAP init) finally gave median ESS 80.6% with flat quartile means almost everywhere (l=250 a lone exception at 3.8% ESS) — **but its C_l came out systematically 3-6x LOW vs the trusted Phase 0 reference** (`results/lmax300_nside256_gibbs_real_double`), worse at higher l.
- [x] **That "3-6x low" result triggered a full matrix-free-SHT correctness audit — the SHT itself is exonerated.** `scripts/debug_matrixfree_sht_accuracy_production_scale.py`: forward synthesis vs `healpy.alm2map` at lmax=300/NSIDE=256, real mask — **5.7e-13 relative error** (machine precision). `scripts/debug_matrixfree_sht_gradient_production_scale.py`: custom-gradient backward pass vs finite differences at the same scale — **max 1.8e-7 relative error** (also machine precision; the lmax=15/lmax=12-only prior test coverage never actually contradicted this). The forward+backward SHT is bit-perfect at production scale.
- [x] **Actual root cause: an apples-to-oranges test setup, not a bug.** The trusted reference chain (`scripts/submit_gibbs_L300_double.slurm`) uses `--map_steps 2000 --map_lr 0.01 --n_lfs 20`; every ad-hoc benchmark chain this pass used `--map_steps 0 --n_lfs 10` — no MAP initialisation, so the chain has to climb from a naive start (psi≈5.0e9) to the true posterior mode (psi≈4.7e8) via burn-in alone, exactly matching the observed slow, l-dependent climb. **Re-run matching the reference's actual settings (`--map_steps 2000 --map_lr 0.01 --n_lfs 20`, `n_burnin=500`, `n_samples=1000`) matches the Phase 0 reference C_ℓ to 1-3% at every probed l (ratios 0.986-1.025, l=2 through 299)** — no bias, fully validated.
- [x] **Remaining, expected limitation: ESS at l=200-250 is still modest (2-4%) at only 1000 samples**, even with correct MAP init — matches Phase 0's own historical situation (their float64 baseline was accepted as "Phase 0 ✓" with similarly imperfect high-l ESS). Not a correctness problem — cheap to fix by running more samples (0.34-0.6s/sweep) if a specific analysis needs tighter high-l constraints.
- [x] **Multi-chain R-hat test — PASSED 2026-07-13.** 4 chains, `--map_steps 2000 --map_lr 0.01 --n_lfs 20`, `n_burnin=1500`, `n_samples=3000`, real Planck data, lmax=300 (job 11584886/87/88/89, `results/lmax300_nside256_gibbs_real_matrixfree_rhat/`). C_ℓ R-hat: max=1.030, median=1.005, 0% above 1.1 — **better than the Phase 0 dense-SHT reference itself** (max=1.014, median=1.001, computed on the same 4-chain reference with the same Gelman-Rubin code, but only 1000 samples/chain). alm-block R-hat is high in both (new: median=1.45, max=8.27, 83% >1.1; reference: median=1.60, max=7.13, 89% >1.1) — the pivot is *not worse* than the already-accepted Phase 0 baseline on this axis, consistent with `achievements.md`'s note that alm R-hat inflation at n≈90k is expected gradient-noise behaviour, not a regression.
- [x] **Tail-ESS check (Standing discipline: R-hat alone isn't enough).** Raw ESS on ln C_ℓ (TFP cross-chain ESS) is *lower per-sample* than the dense reference (new: median=31.4/12000 draws vs reference: median=129.8/4000 draws — roughly 4x worse sample efficiency, plausibly from the step-size adaptation settling higher: 0.157-0.163 vs reference's 0.105-0.113, with accept rates 0.55-0.65 vs 0.60-0.82). **But net throughput is what matters for production planning: ESS per wall-clock second is ~31x better for the pivot** (0.0182 ESS/s vs 0.00058 ESS/s), because the per-sweep cost dropped ~600-1000x while per-sample efficiency only dropped ~4x. Net verdict: gate passed; if a future analysis needs tighter per-sample efficiency, re-tune target-accept/step-size before scaling — cheap to iterate at 0.34-0.6s/sweep.
- [ ] **Optional follow-up (not blocking):** re-tune HMC target accept-rate/step-size-adaptation for the matrix-free path specifically — the reference's fixed/adapted step size regime (0.10-0.11, accept 0.6-0.82) mixes ~4x more efficiently per-sample than the pivot's (0.16, accept 0.55-0.65); recovering that would make the throughput win even larger. Skip unless Phase 2 chains show it matters.

## 2. The real-data run — Phase 2's science headline (⚠ REFRAMED 2026-07-13, see `literature_review_2026-07.md`)

**The A_L anomaly is no longer live**: Planck PR4/NPIPE likelihoods (especially HiLLiPoP) report it much weakened/consistent with ΛCDM, and ACT DR6 lensing shows no excess. The honest pitch is now one of: (a) **the A_L post-mortem** — a joint (alm, C_ℓ, φ) posterior on Planck 2018 vs PR4 maps showing where in the joint space the anomaly lived and how it dissolves, the first fully-propagated-uncertainty account of its resolution; or (b) **internal-consistency machinery as the product** — the joint posterior as the principled lensing-consistency test for SO/LiteBIRD data, demonstrated on Planck. Phase 0 already runs on real Planck data, so marginal cost is small once Phase 2 validates.

A CG solve built from autodiff of `psi_lensed` (mirroring `_cg_grad_fn`'s use of `_psi_tf_raw`) would target the correct conditional exactly; the open question is whether the diagonal preconditioner still near-diagonalises `(L∘Y)^T N^{-1} (L∘Y)` well enough for fast PCG convergence, since lensing breaks the ℓ-diagonal structure the current preconditioner assumes. Not worth pursuing unless HMC-on-both-blocks (the current path) becomes a proven throughput bottleneck at lmax=300 — gate 1 passed MARGINAL, so no urgency.

## Standing discipline

- **One critical path**: HMC-pivot validation → Phase 2 gates → Phase 2 validation + paper. Anything not on it waits.
- **Precision rule**: fp64 end-to-end unless a mixed scheme with fp64 accumulation is validated against fp64 chains (the float32 false convergence is the standing counterexample).
- **Dense-reference discipline**: every new sampler/operator is validated against an exact small-scale reference before production — this has caught five real bugs so far (see `achievements.md`); don't skip it under time pressure.
- **Claims hygiene**: every "first" carries scope qualifiers and nearest-prior-work citations (Millea+2020, MUSE, delensalot); re-check arXiv for curved-sky MUSE before each submission milestone.
- **R-hat on C_ℓ alone is not convergence** — chains drifting together from the same start fool it; check the alm block and tail-ESS trends too (the messenger post-mortem's lesson).
- On dine2/cosma8 reused nodes, scripts need a job-private `$TMPDIR` (autograph cache collision).
